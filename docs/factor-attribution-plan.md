# 因子归因页（backlog #4.4）

## 一、它回答什么

一次回测跑完，收益曲线和成交明细都有了，但没人告诉你**赢的那些单和输的那些单，在买入那一刻到底哪里不一样**。这一页就是回答这个问题：

> 把已平仓的成交配成一笔笔交易，按净收益分成胜单 / 败单两组，比较两组在**入场信号日**的指标取值，看哪些指标能区分胜负。

它跟已上线的**因子检验**（#5）是两件事，别混：

| | 因子检验 #5 | 因子归因 #4.4 |
|---|---|---|
| 样本 | 全市场面板：每天每只票 | **一次回测的成交**：每笔平仓交易 |
| 标签 | 前瞻收益（未来 N 天） | **事后盈亏**（这笔单赚了还是亏了） |
| 方向 | 指标值 → 收益 | 胜负 → 指标值（**方向相反**） |
| 收益口径 | 裸收益（不含成本滑点） | **净口径**（已扣双边成本、印花税、滑点） |
| 问题 | 这个指标能不能选股 | 这批单为什么赢 / 输 |

一个是"能不能预测"，一个是"已经发生了，怎么解释"。

## 二、样本从哪来

**不重跑回测**。回测结果里已经存了全量 trades（`portfolio_backtest.py:99-112` 落库，`backtest_history.result_json`），直接读 `read_backtest_history(history_id)["result"]["trades"]`。仓库里三个"重跑"入口（策略实验 replay、追踪 rerun、launch）都不是干这个的，再造一个就是第四份口径。

能归因的历史记录 = `result.trades` 非空且能配出足够多的平仓交易。类型上覆盖 `portfolio`（组合回测）与 `condition_research`（条件研究），两者 trade 字段一致（都有 `date` / `signal_date` / `market` / `code` / `direction` / `pnl` / `cost_basis`）。

⚠️ 历史只留最近 20 条（`BACKTEST_HISTORY_LIMIT`），用户想归因的旧回测可能已被淘汰 → 必须给出"这条记录不存在"的明确提示，而不是空列表。

## 三、口径（定死的部分）

### 3.1 配对：FIFO，未平仓不参与

- 按 `(market, code)` 分组、按成交日排序，**FIFO** 配对（与 `portfolio_backtest/report.py::_average_holding_days` 同口径）：每个 SELL 匹配最早的未平仓 BUY。
- **期末还持有的 BUY 不算样本**——没有已实现收益，浮盈不能当胜单。数量单独上报为 `open_positions`。
- SELL 多出来配不到 BUY（数据源异常）→ 丢弃并上报 `orphan_sells`，不静默吞掉。
- 每笔交易记：
  - `signal_date` = BUY 的 signal_date（缺失时回落到 BUY 的成交日）
  - `entry_date` / `exit_date`、`holding_days` = 该股在 [entry, exit] 之间的交易日数（读行情时顺手数出来，不用自然日糊弄）
  - `return` = `pnl / cost_basis`（**净口径**）
  - `win` = `return > 0`（`return == 0` 归败，保守）

### 3.2 指标取值：入场信号日，缺失即丢弃

- 涉及的股票 = 样本里 `(market, code)` 去重，用 `list_stock_refs` 全量后过滤（不逐只查库）。
- 区间 `[min(signal_date), max(signal_date)]`，warm-up 用 `recommended_bars` 而不是 `minimum_bars`（照抄 `factor_test/panel.py:167` 的理由：用 minimum 会让 `rsrs_zscore` 这类指标整段 NaN，静默缩掉样本）。
- `read_many_stocks` 批量读 + `FORMULA_REGISTRY.formula(fid).calculate(group)` 整段算，再按 `signal_date` 取点。不建三维面板——只有几十只票，O(股票数 × 天数 × 指标数) 比因子检验小两个数量级。
- **缺失即丢弃，绝不填 0**：信号日没有行情行、或指标值为 NaN / inf → 这笔交易在该指标上被丢弃，按指标计数上报 `missing_samples`。RSI=0 和"这天没有 RSI"是两回事，填 0 会凭空造出一个"胜组 RSI 极低"的假结论。
- 一只票完全读不到 → 它的所有交易整体剔除，并上报。

### 3.3 统计：差值 + 块置换 + BH-FDR

- **主度量 = 差值**：胜组均值 − 败组均值。**绝不用比值**——指标值可以取负，两个负数相除会读成"差三倍"，方向还可能反过来（这个坑在 #5 里已经踩过一次）。
- **标准化差 = 差值 / 合并标准差**（Cohen's d 风格），只用于跨指标排序和"最强区分指标"的说法；对外主数仍是带量纲的差值（"胜组 RSI 平均低 6.2"比"标准化差 0.35"好懂）。
- **置换检验**，零假设 = 胜负与指标取值无关：
  - 独立单位是**交易日，不是成交笔**。同一天下的几笔单共享当天的市场环境，同一只票的连续交易也相关，逐笔打乱会把 p 值压得过小。
  - 做法：样本按 `signal_date` 排序后用 `block_permutations` 按位置分块搬动**标签**；块长按 `ceil(20 × 成交笔数 / 信号日数)` 换算，语义就是"约 20 个连续交易日的段"。复用 `swing_research/scoring.py::block_permutations`，不写第二套。
  - 统计量 = 置换后的（胜均值 − 败均值），单尾计数（观测为正则数 ≥ 观测的次数，反之数 ≤ 的），`p = (1 + reached) / (1 + permutations)`。
  - p 值下界 `1/(1+permutations)`：alpha 比它还低时，reason 直说"这个检验达不到你设的显著性水平"，而不是让人以为指标全是垃圾（照抄 `factor_test/service.py::_reason`）。
- **多重比较**：所有指标**一次性** `benjamini_hochberg`，绝不逐个调（逐个调等于没校正）。

### 3.4 护栏（全部显式上报，不静默）

| 护栏 | 阈值 | 触发时 |
|---|---|---|
| `MIN_TOTAL_TRADES` | 10 笔 | 可配对的平仓交易不足 → **整个归因不跑**，reason 说明 |
| `MIN_GROUP_TRADES` | 20 笔 | 胜组或败组不足 → 仍出数，但标「样本不足」、**不判显著**（`significant=None`） |
| `MIN_SIGNAL_DAYS` | 10 天 | 不同入场信号日不足 → **不做置换**，只给描述性差值并注明"样本太集中，无法估计噪声门槛" |
| 恒定指标 | 标准差 0 | 跳过，note 说明 |

阈值参照 #5 的 `MIN_CROSS_SECTION=20`，按"每组最少样本"平移过来；#5 那套是按交易日设的，对"按成交笔数"的归因不适用，所以这里是新设的四个数，不是抄的。

### 3.5 输出

- 概览：来源回测（id / 类型 / 区间）、配对交易数、胜 / 败笔数、未平仓数、丢弃数、信号日数、指标数、通过 FDR 的数量。
- 每指标一行：中文名、胜组均值、败组均值、差值、标准化差、两组样本数、p、FDR 后的 p、是否显著、note。
- **排序：先显著后不显著**，显著组内按 |标准化差| 降序（同 #5 的写法）。绝不按未校正的 p 排。
- `reason` 文案直给结论：没有指标通过 → "没有一个指标能在噪声门槛之上区分胜负"；有 → 点名最强的一两个，说清方向（胜组更高还是更低）和幅度。
- `boundaries`（页面固定展示，照抄 #5 的做法）：
  1. 收益是**净口径**（已扣双边成本、印花税、滑点），不是裸价格收益；
  2. 取的是**入场信号日**的指标值，不是成交日——信号日与成交日不同的单要留意；
  3. 胜 / 败是**事后**标签：这是解释工具，不是预测模型；
  4. 未平仓的单不参与；
  5. 没有样本外切分，结论只解释这一次回测。

## 四、刻意不做的

- **不做多因子回归 / 收益分解**（不拆 beta、行业、风格）。单指标分组对比 + 多重检验校正已经够回答"哪不一样"，回归会引入共线性解释的坑，而且样本量（几十笔单）根本不够。
- **不给调参建议**。不说"把 RSI 阈值改到 30"——那是候选库与策略发布的事，归因只负责解释。
- **不做跨回测合并**。一次只分析一条历史记录，合并会让"同一次回测的市场环境"这个前提失效。
- **不自动重跑回测**（见第二节）。

## 五、成本

- 读取：几十只票 × 一段区间，一次 `read_many_stocks` 批量搞定，比因子检验的全市场两遍扫描小两个数量级。
- 计算：整段 `calculate` 一次出所有输出，与 #5 同路径。
- 置换：200 次 × 指标数（约 30）× 样本数（几十~几百笔）——纯 numpy 切片，毫秒级。
- 走 job runner 的原因不是慢，是**可能慢**（回测跨度大、成交多、股票杂），与 #5 保持一致。
