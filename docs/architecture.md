# 指标实验室架构

## 目标

应用是单机、单用户的本地行情工具。通达信 `.day` 文件只是原始输入，项目自己的 DuckDB 是唯一行情主库；筛选、行情页和所有回测只读取数据库，不在请求期间打开 `.day` 文件。

```text
通达信 vipdoc/*.day ──┐
                      ├─ LocalDayImporter ──┐
内置 TDX 日线客户端 ──┘                     │
                                             ▼
                                   market.duckdb
                                             │
              ┌──────────────────────────────┼──────────────────────────────┐
              ▼                              ▼                              ▼
       IndicatorCache                 行情页/指标                    回测与策略适配
       版本化派生指标                  DuckDb adapter                 自有交易核心
              │                              │                              │
              └─────────────── ScreenEngine / Backtest / Portfolio ─────────┘
```

## 分层规则

- `market_data/` 定义项目自己的行情模型、`.day` 解析器、增量导入器、DuckDB repository 和业务适配器。
- `indicators/` 保存可重建的版本化指标缓存，并负责导入后的批量预热；缓存不是行情事实源。
- `tdx_protocol/` 只实现在线日线同步需要的 TCP 帧、证券列表、日线请求和二进制解码；不暴露上游对象给业务层。
- `formulas/` 是无副作用的数组计算层。公式函数由 `formulas/tdx_math.py` 自己实现，输入输出均为项目内部的 NumPy/Pandas 数据。
- `screening/` 负责条件合并、批量读取、单标的容错、进度和导出，不处理网络或文件格式。
- `backtest/` 负责单标的交易模拟和绩效计算；`portfolio_backtest/` 负责动态候选、固定槽位和补位；`strategy_fitness/` 复用这些交易语义完成时间切分评估。
- `web/` 只负责 Pydantic 校验、任务提交/轮询和安全错误响应。
- `web-ui/` 只负责导入/同步操作、状态展示、表单和图表。

运行时不安装或导入外部行情框架。历史适配模块仅保留早期调用方的兼容名称，内部已经改为项目自己的 `.day` 适配器；默认应用使用 `DuckDbMarketDataAdapter`。

## DuckDB 数据层

默认数据库路径为 `${SELECTOR_DATA_DIR}/market.duckdb`；未设置环境变量时使用用户数据目录。Docker 将 `SELECTOR_DATA_DIR` 设置为 `/data/market`，并通过独立的 `market_data` named volume 持久化。

核心表：

- `instruments`：市场、代码、中文名、品种类型、源路径、首末日期、K 线数量和源状态；
- `daily_bars`：原始价格口径的 OHLCV、成交额、来源、K 线状态和导入时间，`(market, code, trade_date, price_basis)` 唯一；
- `source_files`：源根目录、相对路径、文件大小、修改时间、SHA-256 和导入状态；
- `data_meta`：schema 版本、最近一次本地导入和在线同步时间。
- `indicator_cache`：按标的、周期、价格口径、内置公式版本和行情指纹保存完整指标数组与信号数组；缓存失效后可从 `daily_bars` 重建。
- `custom_indicator_cache`：按标的、周期、价格口径、自定义公式哈希、参数哈希、公式引擎版本和行情指纹保存自定义输出。

行情事实写入只由导入/同步任务执行，并使用独立事务和进程内 writer lock；派生指标缓存可由预热任务或业务请求按需填充。读操作每次建立独立只读 DuckDB 连接。全市场筛选、组合回测和策略适配通过一次批量查询得到各标的分组，避免逐文件打开 `.day`。

本地导入或在线同步完成后会分批预热三个内置公式；已有数据库或预热未完成时，筛选和回测会按需填充缓存。缓存基于完整、有序行情的 SHA-256 指纹，公式版本变化、行情更新或价格口径变化都会自动跳过旧缓存。自定义公式按公式内容、参数和引擎版本独立缓存，不同参数不会互相复用。

schema 版本变化时，初始化逻辑会先生成带时间戳的 `.bak-*.duckdb` 副本，再执行升级；更高版本数据库会拒绝打开，避免静默破坏数据。数据库文件和备份均不提交 Git。

## 本地导入

`POST /api/v1/market-data/import-local` 接收 `vipdoc` 根目录，只读扫描 `sh/lday` 和 `sz/lday`。文件名决定市场、代码和证券类型：股票/B 股、基金/ETF、指数和债券均使用对应的价格/成交量系数；未知代码段跳过并记录原因，不使用股票系数兜底。

首次导入解析全部历史。之后先比较 `mtime_ns + size`，只有文件变化才计算 SHA-256；内容变化则重新解析，并在一个事务中替换该标的全部本地记录。解析失败保留旧数据；源文件消失只把 `source_files.status` 标为 `missing`，不删除历史。15:05（Asia/Shanghai）前的当日记录为 `provisional`，筛选和回测默认排除；收盘后的下一次同步会重新导入并转为 `completed`。

应用启动时若在 `SELECTOR_VIPDOC_PATH` 或 `/data/vipdoc` 发现 `.day` 文件，会提交一个后台增量导入任务；启动过程不等待全量解析，行情页会识别该任务并在完成后自动刷新数据库状态和标的列表。没有本地文件时不会创建空导入任务。

源文件不会被追加、覆盖、截断或修改。任务结果包含发现、成功、跳过、失败、未变化文件数，以及新增/替换标的、K 线数和失败原因。

导入范围是显式配置项：市场支持沪深全部、仅上海和仅深圳，证券类型支持股票、基金、指数和债券，板块支持主板、科创板、创业板、B 股、基金、指数和债券。省略某个维度或传空数组表示该维度不限制；类型和板块同时设置时取交集。板块由市场和代码段识别（SH `60` 主板、`68` 科创板、`90` B 股；SZ `00` 主板、`30` 创业板、`20` B 股）。范围只决定本次扫描和写入哪些文件，排除的文件不会删除数据库中已有历史。

## 在线同步

`tdx_protocol` 是项目内置的最小同步客户端，支持：

- TCP 建连、初始化帧、超时、有限重试和服务器故障转移；
- `get_security_list_all`；
- `get_security_bars(..., DAY, ...)`；
- TDX 日期、价格变长整数、成交量自定义浮点和指数附加字段解码；
- 空响应和截断响应的安全处理。

在线同步直接写 DuckDB，不写回 `.day`。同一日期已有 `source='local'` 时永不覆盖；`source='online'` 可以更新；缺失日期可以插入。已有数据时先探测最近两根日线，只有发现新增或变化才拉取配置窗口；完整历史仍优先由本地导入提供。

`.day` 文件不包含中文名，因此本地导入只建立代码和行情记录；在线证券列表的 `name` 字段会写入 `instruments`，并在扫描结果 JSON/CSV 和页面中透传。名称刷新失败不会影响已有行情扫描，结果显示 `—` 作为占位。内置公式的扫描结果只透传注册表中的用户可选输出，公式内部中间数组仍保留在指标缓存中；自定义公式透传其命名输出。

在线同步在请求日线前应用同一套市场、证券类型和板块范围，因此未选中的品种不会产生行情请求。一键同步会先导入配置的本地 `vipdoc`；本地导入成功后，在线阶段优先使用 DuckDB 中已导入的标的，避免为已有本地数据再次拉取完整证券列表。筛选、组合回测和策略适配复用该范围模型；没有设置类型或板块过滤时查询全部已导入且可识别的品种，不设置项目级默认偏好。

## 公式和回测一致性

项目自有 `REF`、`SMA`、`EMA`、`MA`、`LLV`、`HHV`、`SUM`、`COUNT`、`BARSLAST`、`CROSS` 等函数，保留现有 NaN、预热和 `SMA(..., 3.2, 1)` 语义。公式一的负分母、公式二显式 `REF(A,20)` 间隔和自定义公式的因果边界均有回归测试。

指标缓存始终基于完整历史计算，再由筛选或回测截取日期窗口；不会只对可见窗口计算，从而保留均线、`REF`、`EMA` 和穿越信号的预热语义。缓存异常只影响性能，不会替代原始行情或阻断直接计算回退。

单股交易核心使用下一根开盘/收盘成交、100 股/份整数、佣金最低收费、印花税、滑点和资金不足时的 reduce 规则。股票档案为佣金 `0.0003`、最低 5 元、印花税 `0.001`；基金/ETF/指数/债券档案为佣金 `0.00005`、最低 0.1 元、无印花税。非股票结果标记为虚拟研究回测。

## API

- `POST /api/v1/market-data/import-local`
- `POST /api/v1/market-data/sync-online`（仅在线更新）
- `POST /api/v1/market-data/sync`（一键本地增量导入后在线补缺）
- `GET /api/v1/market-data/store`
- `GET /api/v1/market-data/jobs/{job_id}`
- `GET /api/v1/market-data/local/instruments`
- `GET /api/v1/market-data/local/{market}/{code}/bars`
- 既有公式选股、单股回测、组合回测和策略适配 API 保持路径不变，但只读取 DuckDB。

行情查询接口不需要 `vipdoc_path`；本地导入和一键同步可以指定该参数，省略时使用 `SELECTOR_VIPDOC_PATH` 或 `/data/vipdoc`。纯在线更新不读取本地目录。自定义 universe 文件仍可由筛选/回测请求指定，但其中的行情数据来自数据库。

## 测试重点

单元测试覆盖 `.day` 32 字节记录、所有已识别品种系数、残缺尾部、增量指纹、临时 K 线、本地优先、DuckDB 去重/批量查询、TDX 协议帧和响应、公式结果、逐笔交易和组合补位。集成测试覆盖导入任务轮询、在线 fake client、空库/错误路径和全部业务读取路径。
