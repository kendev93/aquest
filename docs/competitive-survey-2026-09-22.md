## 二、三条真正值得做的（已过四条门槛）

### #20 累计试验次数校正 —— 最契合，也最缺

**别人怎么做**：Deflated Sharpe Ratio（Bailey & López de Prado, 2014）的核心输入是 `n_trials`，
定义是**整个研究项目里试过的配置总数，包括你丢弃的那些**。原文强调的那句话值得抄在这里：

> "If you forget the 80 failed experiments, you fool yourself."
> —— 只数成功的试验，会骗到自己。

门槛本身不复杂：

```
E[max SR] ≈ (1 − γ)·Z(1 − 1/N) + γ·Z(1 − 1/(N·e)),  γ = 0.5772（欧拉常数）
```

N=300 时零噪声的期望最优 Sharpe 约 0.28；N=15000 时约 0.44。**试得越多，同样一个结果越不值钱。**

**我们的现状（已核对代码）**：

- 条件研究的噪声门槛是 **max-T 置换**（`condition_research/mining.py::_permutation_max_lifts`），
  它校正的是**单次运行内**并排检验了多少个条件——这一步是对的，等价于单次 N。
- 但 `backtest_history` 表结构（`market_data/store_base.py:455-465`）只有
  `history_id / backtest_type / 时间 / request / result / summary`，**没有任何累计试验计数字段**。
- 也就是说：跑第 50 次条件研究和跑第 1 次，用的是同一个门槛。累计试过 50×300 = 15000 个条件的
  事实，在统计上完全没有被记账。

**为什么这条最贵**：我们的卖点是"结论能不能被证伪"，而多重检验校正做得不彻底 = 最大的证伪缺口。
而且这个缺口是**静默**的——每次结果看起来都算过了，没人会发现分母少算了 50 倍。

**建议形态**：加一张"研究台账"，累计已检验的条件数 / 参数组合数（含失败的），
把噪声门槛与 DSR 的分母从"本次 N"换成"累计 N"。组合回测与策略追踪侧直接上 DSR。

**坑（文献明确列出）**：① 只数成功试验；② Sharpe、收益、T 的频率不一致（年化 Sharpe 配日频 T 会出
 nonsense）；③ 把参数细扫当成独立试验（高度相关的试验要折算成"有效 N"）。第三条对我们尤其重要——
 参数敏感性分析产生的邻域点高度相关，不能按原始点数直接累加。

### #21 最小跟踪记录长度（MinTRL）—— 把硬编码阈值换成可算的数

**别人怎么做**：MinTRL 回答"以你观察到的 Sharpe 和这个收益分布的形状，还要多少样本才能在 95% 下
拒绝『真实 Sharpe = 0』"。它是 DSR 的反解，公式成熟、实现半天。

**我们的现状**：策略追踪里"观察段 < 20 交易日标『样本过短』"——**20 这个数是拍的**。
（`portfolio_backtest/tracking.py::MIN_OBSERVATION_BARS`）

**为什么值得换**：硬编码阈值我们说不出口理由。MinTRL 把同一个判断变成"以你现在的 Sharpe 0.6、
偏度 −0.4，需要 14 个月才能谈显著性；你只有 3 个月"——这才是可证伪的口径，
而且直接复用我们已有的收益序列。

---

### #22 行情数据健康检查 —— 静默出错类，qlib 有，我们没有

**别人怎么做**：qlib 文档把 "Checking the health of the data" 作为数据层的独立一节，与数据准备并列。

**我们的现状（已核对）**：`market_data/maintenance.py` 只有备份、压缩、保留策略，**没有任何
缺口 / 停牌 / 异常价 / 复权断点的检测**。

**为什么危险**：所有研究结论都建立在"行情没洞"这个前提上。缺 bar、长期停牌被当成"价格不变"、
复权断点、异常价（0 或单日跳变）都会**静默**污染结论，而且越往下游越看不出来。
按"错误可见性"排序，这类正是最该收口的。

**建议形态**：一个只读的体检报告——每只标的的缺失交易日数、最长连续缺失、疑似停牌段、
价格跳变超过阈值的日子、与全市场的交易日对齐情况。出报告，不做自动修复。

## 三、一条要留意的（不紧急，但结论会虚高）

### #23 涨跌停不可成交

**别人怎么做**：果仁网被反复提到的优势是"内置了非常真实的 A 股撮合逻辑（自动处理分红、停牌、
**涨跌停买不进**等坑）"。第三方评测把它列为核心卖点。

**我们的现状（已核对）**：`portfolio_backtest/models.py:72-75` 有
`commission / min_commission / stamp_tax / slippage`——成本模型是齐的。
但**没有涨跌停约束**：涨停日的买入、跌停日的卖出在回测里都成交了。

**影响方向是单向的**：条件研究挑出来的往往是强势股（刚启动、正在冲），这类标的恰好最容易撞涨停。
所以缺这条约束会**系统性高估**回测结果，而不是随机误差。

**建议**：做成开关，默认关闭并在报告里显式标注"未考虑涨跌停不可成交"。
开着的代价是成交率下降、样本变少；关着要知道自己关了什么。

## 四、明确不借鉴（附理由，避免下次重查）

| 别人的功能 | 不借鉴的理由 |
| :--- | :--- |
| qlib 的 ML 全流程（LightGBM/LSTM/RL） | 定位不同。我们做"自定义指标 + 统计检验"，引入模型层会稀释卖点，且不可证伪性大增 |
| qlib 的 Alpha158 / Alpha360 因子库 | 我们是"你自己定义、我来检验"，不是"我给你 158 个因子"。且已有内置指标 + TDX 导入 |
| qlib 的 Online Serving / 模型部署 | 不碰实盘（门槛 1） |
| qlib 的 Recorder 实验管理 | **不是缺，我们已有**：`backtest_history` + 历史对比（#16）已覆盖记录与复现 |
| qf-lib 的事件驱动回测 | 日线研究不需要事件驱动架构，重写的代价远大于收益 |
| qf-lib 的 PDF 报告导出 | 偏"看得更细"，不强化可信度（同 §五 对 #17 的判断） |
| 果仁网零代码拖拽选股 | 受众不同：它服务不懂编程的新手，我们服务要验证想法的人 |
| 聚宽/米筐的社区 + 策略克隆 | 依赖用户基础，现在没有 |
| 水母量化的自动交易对接 | 不碰实盘（门槛 1） |
| BigQuant 的 AI 投研 | 同 §五 对 #12 的判断：要做必须带工具足迹卡，是个大工程 |

## 五、一条已经做对的（核对后确认，不用改）

**防未来函数**：`formulas/tdx_math.py:26` 与 `formulas/custom.py:748` 都强制 `REF` 周期为**非负**，
负偏移直接抛错；自定义公式的函数集是白名单制（`custom.py:47,90`），没有能向前取值的函数。
这条比 qf-lib 的通用防护更硬——白名单保证了结构上的不可能，而不是靠运行时检查。

顺带记录一个文献点名的、我们**天然免疫**的泄漏方式：全局归一化（用全历史 mean/std 做 z-score）。
我们的公式引擎按序列求值，没有全序列归约函数。

## 六、产品形态层面的观察（不是功能，是特点）

- **qlib 的涨星方式与 TSP 完全不同**：不是靠"涨得快"，是靠机构背书 + 6 年积累 + 学术引用。
  它的 open_issues 480 个，说明真用的人多。这印证第一轮的判断——**fork/星比才是健康度信号，
  星数绝对值不是**。
- **国内商业平台的共同卖点是"撮合真实性"而不是"策略多"**。果仁网被夸的是分红/停牌/涨跌停处理，
  聚宽被夸的是数据质量。说明用户真正为此付费的是"结论可信"，不是"功能列表长"。
  这跟我们的定位是同一个方向。
- **没有任何一个对标对象把"多重检验校正"做成卖点**。DSR/PBO 在学术界是standard，
  在工程产品里几乎看不到（只在 tw_stocker 这类个人项目里偶现）。
  这既是我们的差异化空间，也说明**没有现成的产品形态可抄**——得自己设计呈现方式。
