A股策略研究是一个**日线级别的研究工具**：它帮你在 A 股日线上确认一个想法有没有证据，
它不连接券商、不产生下单。这一点决定了下面所有功能的边界——每个页面都明确写出了
「它能回答什么」和「它不能回答什么」，读的时候请特别留意后者。

## 这些页面怎么串起来

| 阶段 | 页面 | 在这一步做的事 |
| :--- | :--- | :--- |
| 有想法 | 公式选股 | 看这个想法今天能筛出多少票 |
| 验证想法 | 买卖条件研究 / 波段研究 / 因子检验 | 用置换检验判断它是不是运气 |
| 配成策略 | 组合回测 / 策略适配性 | 把规则变成可执行的组合，算扣费后的收益 |
| 放手不管 | 策略实验室 | 让系统搜索参数组合（记得榜单自带挑选偏差） |
| 往前观察 | 策略追踪 | 规则冻结后，看它在没见过的数据上还灵不灵 |
| 事后复盘 | 因子归因 / 历史对比 | 解释为什么这次赚了、为什么这版比那版好 |
| 沉淀 | 候选库 | 把带完整证据的条件留下来，之后还能找回去 |

## 全站共通的三条口径

1. **只做 A 股日线**。主板、科创板、创业板，不含 ETF 与基金、指数、债券、B 股；也没有分钟数据，所以盘中级别的策略没法在这里验证。
2. **信号收盘确认、次日成交**。回测里的收益不等于「今天看到就买到」的收益，这是所有回测页面的默认假设。
3. **凡是看上去不错的发现，都要先问它能不能被随机解释**。各处用到的置换检验、错误发现率校正，以及「这到底是第几次试出来的」这类追问，意义都在这一条上，页面不会替你省略它们。

## 1. 公式选股（/aquest）

*筛选与挖掘*

把交易想法拆成可勾选的条件，在全部 A 股的最新日线上扫一遍，得到当天有哪些票同时满足。

### 什么时候用它

- 每天收盘后想要一份当天命中的候选名单
- 先看看一个信号在当前市场上大概能筛出多少票，再决定要不要花时间研究它

### 操作步骤

1. 在「选择信号」区勾选要用的条件：可以是内置信号的复选框，也可以切到「指标条件」，用某个指标的数值输出做大于、小于、上穿、下穿的比较
2. 勾选多个条件时，决定它们之间的关系：全部满足、任一满足，或者至少满足 N 个
3. 选择品种范围（沪深全部、仅上海、仅深圳、自定义列表）以及证券类型和板块；不勾选类型或板块表示不限制
4. 点击「开始筛选」，结果表会给出命中的标的、具体命中了哪些条件，以及各排序指标的取值
5. 配置区顶部的「筛选方案」可以命名保存整套设置（信号 / 条件 / 范围 / 板块 / 并发），存在服务端数据库里，换浏览器也在；之后可以加载、改名、删除、覆盖
6. 选好一个方案点「一键选股」= 载入这套设置并立刻扫描；只想还原表单不扫描就用「只加载设置」
7. 结果表最左侧的「存组」可以勾一部分票（或整批）保存成股票组，之后回到本页的「股票组」面板就能看到它们入组之后涨跌了多少、有没有跑赢全市场
8. 股票组默认折叠：一行上就有入组日期、筛选条件和近 1 月 / 近 3 月的收益；点开某一组才会去算「入组至今」的完整曲线
9. 组名可以随时改，筛选条件会跟着组一起存下来

### 它能回答什么

- 某一个交易日上，哪些标的满足了这组条件
- 这组条件在全市场能命中多少票。命中过多时，真正决定买谁的是排序规则而不是条件本身
- 上次扫出来的那批票后来怎么样了（存成股票组之后可以一直回来看）

### 它不能回答什么

- 只回答「这天是否满足」，不回答「按它买了能不能赚」，后者是回测类页面（买卖条件研究、组合回测）的事
- 当日收盘价尚未定稿时不进结果，所以盘中跑出来的结果缺少最后一个交易日是正常的

### 口径提醒

- 品种范围只有 A 股：主板、科创板、创业板。ETF 与基金、指数、债券、B 股都不在候选池里，因为 ETF 跟踪同一指数会让排序结果高度雷同，指数本身不可交易，B 股流动性枯竭
- 内置指标按板块套用对应的量价系数，不是全市场共用一个系数
- 股票组的表现是「入组那天收盘价等权买入、之后不动」的曲线，不含佣金、印花税和滑点；入组当天没有收盘价的票（新股、停牌）不计入，会在结果里单独点名
- 折叠行上的「近 1 月 / 近 3 月」和展开后的「入组至今」是两套口径：前者所有组用同一个窗口，组之间可以直接比；后者每组起点不同，只能一组一组看
- 近 N 个交易日按交易日数算，不按自然日：假期不算进去。窗口里数据不够时会标出实际天数，不会拿 41 天的数据当 60 天看
- 组的筛选条件是保存那一刻的快照，不是回指扫描历史——历史每种类型只留最近 20 条，等历史被淘汰时只有这个快照还能回答「这批票是按什么选出来的」
- 从买卖条件研究带过来的只有买入侧：选股是「某一天是否满足」的一次性扫描，不涉及什么时候卖

## 2. 买卖条件研究（/condition-research）

*筛选与挖掘*

给一条基础买卖规则（甚至可以只给一侧），系统逐只股票独立回测，从「盈利的交易和亏损的交易到底差在哪」里挖掘候选阈值条件，再用时间切分做验证。

### 什么时候用它

- 手上有一个大致的方向，但不知道具体阈值该设多少
- 想知道某个位置（比如卖出）到底该用什么指标来判断

### 操作步骤

1. 设置基础买入规则和（或）基础卖出规则。两侧不能同时留空：卖出留空（勾选「持有到期末」）表示买入后持有到区间最后一天平仓；买入留空（勾选「持续满仓」）表示每次离场后下一个交易日立刻再买入
2. 可以指定排序规则（排序指标、方向、槽位数），有了它，结果会额外告诉你在有限槽位下这条条件还有没有意义
3. 选择品种范围、日期区间、持有天数和交易费用
4. 点击开始挖掘，系统会逐个把候选条件按证据强度排出来
5. 勾选候选，可以追加到对应方向的基础规则上再跑一次；也可以用「用这套规则去跑组合回测」，把买卖规则、排序规则和槽位数一起带过去
6. 把调好的整套设置存成「研究方案」（命名保存、改名、覆盖、删除都在第一屏的方案区），下次「一键研究」直接载入并开始，不用重新填一遍

### 它能回答什么

- 在买入或卖出的位置上，哪个指标、哪个方向、哪个阈值能把胜率拉开
- 这个拉开是贯穿始终，还是某一段行情的运气，分段检验会说明
- 在只能买前 N 名的限制下，这条条件的胜率还剩多少

### 它不能回答什么

- 它是对每只股票独立跑出来的结果，不构建组合、不设持仓上限，所以整池胜率不等于有槽位限制时的组合表现，后者要看表格里的「前 N 名胜率」
- 置换检验校正的是这一次运行内挖了多少个条件；跨运行的累计试验已按「独立数据轮」记账并抬高了判定门槛，但同一段行情反复挖出来的结果仍然高度重叠，页面会明确提示你在同一段数据上重复挖了几次
- 研究方案存的是整套输入（买卖条件 / 范围 / 区间 / 搜索与验证参数 / 费用），不含任何结果——结果依赖当时行情，存下来下次加载的人会以为它还成立。它和历史记录的分工是：历史记「跑过什么」（满了自动淘汰），方案记「还想再跑一遍」（只有显式删才消失）
- 方案里引用了当前不存在的指标或信号时，加载会把它们换成可用项并在提示里写明项数。这不是报错，但换过之后跑的已经不是原来那套条件，先核对再运行

### 口径提醒

- 推荐排序要求三条互相独立的证据同向才算证据充分：信息系数（这个指标本身有没有预测力）、信息系数的信息比率（这个准头稳不稳）、分段同号（是贯穿始终还是某段行情的运气）。三条不同向会明确降级并写明原因
- 挖出来的候选除了大小比较（指标对阈值的 ≥/≤、两个指标之间的大于/小于），还有「上穿 / 下穿」：决策点前一天还在下方、当天翻到上方（下穿反之）。穿越要拿前一交易日的值来比，所以该股第一个交易日、或前一日指标还没算出来的决策点不参与这一类候选
- 高度雷同的条件（相关系数达到阈值）会合并成一条，被合并掉的那些会显式列出来，不会静默消失
- 累计试验按数据区间记账：区间重叠过半算同一轮。同一段数据反复挖不会增加撞好运的机会，所以不计入轮数；换一段完全不同的数据才算新一轮，判定会按轮数校正（校正后的 p 更大，原始 p 仍一并显示）
- 「前 N 名胜率」模拟真实组合：先筛出命中条件的票，再按排序取前 N 名，只看这批真正会成交的样本。命中数不超过槽位数时排序不起作用，这一列就等于全池胜率

## 3. 动态组合回测（/portfolio-backtest）

*回测与验证*

按买入条件产生候选、再按某个指标排名，用固定数量的槽位等额买入；谁先卖出，就由当时排名最靠前的候选补上它的位置。

### 什么时候用它

- 手上已经有一套明确的买卖规则，想知道它在过去一段时间里真正能赚多少
- 比较不同排序指标、不同槽位数、不同止盈止损带来的差别

### 操作步骤

1. 设置买入方式：要么勾选信号组合，要么用规则组写更细的条件
2. 设置卖出方式：卖出信号、百分比或 ATR 止盈止损、移动止盈、指标阈值卖出、两个指标之间的比较卖出，或者干脆持有到期末
3. 选择排序指标和排序方向，这决定了同等条件下先买谁；再设定持仓槽位数
4. 设置初始资金与交易成本（佣金、最低佣金、印花税、滑点），选择建仓方式（每槽等额或固定股数）
5. 选择品种范围、日期区间、调仓频率（每日、每周、每月）和成交方式（下一根开盘或下一根收盘）
6. 在「数据范围」里决定是否排除 ST / *ST / 退市标的（默认排除）；被排除的代码会列在报告里
7. 跑完后查看收益曲线、回撤、逐笔成交明细；确认可用之后可以把这套配置保存成策略

### 它能回答什么

- 这套「规则 + 排序 + 风控 + 成本」的组合在过去这段时间里，扣掉费用后的净收益、最大回撤、胜率、盈亏比和成交笔数
- 退出风控寻优会用训练、验证、留出三段比较止盈、止损和移动止盈的参数表现

### 它不能回答什么

- 普通回测按当前配置回放；退出风控寻优只调整四组风险参数，不会改动买卖规则、排序或标的范围
- 它只解决选票和买卖时机，不做权重优化，每个槽位都是等额买入
- 排除 ST 只能按**当前**股票名称判定：行情库没有历史名称快照，回测会连「当时还没戴帽、后来才变 ST」的股票一起排除，样本比实盘更保守；也无法还原戴帽当天的真实冲击

### 口径提醒

- 信号在收盘时确认，默认按下一根开盘成交（可改成下一根收盘）；止损、止盈、移动止盈走同一条滞后——触发当日收盘后判定、下一根 K 线成交，不按盘中触发价成交。所以回测收益不等于「今天看到信号、今天买入」的收益
- ATR 一律用 Wilder 平滑，和指标目录里的 atr_pct 同一个算法；ATR 周期可以整体设置，也可以按标的覆盖，报告里显示的风控价就是引擎实际在用的那条线。历史口径是简单移动平均，换算法后新旧结果不可直接比较
- 已知未考虑的成交约束：目前没有涨跌停不可成交的判断（涨停日也按买进算了），也不做停牌判断。这两条都会让结果偏向乐观，而且是单向的，因为被挑中的往往正是最容易撞涨停的强势股。它们已记在候选池里，尚未实现
- 成本是模型值（固定费率），不是真实成交时的滑点与冲击成本

## 4. 策略适配性（/strategy-fitness）

*回测与验证*

同一套买卖规则在每一只股票上分别按训练、验证、测试三段回测，按成交样本数、期望收益、盈亏比、回撤和稳定性给出一个可拆解的适配分。

### 什么时候用它

- 规则本身没问题，但想知道它到底适合哪些票
- 在把一套规则交给组合回测之前，先把明显不适合的品种过滤掉

### 操作步骤

1. 设置要评估的买卖规则、品种范围和时间区间
2. 设置三段时间切分的比例和门槛：最少成交笔数、最大回撤容忍度
3. 点击开始，系统会按时间顺序跑三段，给出每只标的在各段的表现
4. 按适配分排序，看哪些标的在训练段之后依然走得下去，样本外那段才是重点
5. 挑出适配的品种，交给组合回测按当前排序指标实际跑一遍

### 它能回答什么

- 这套规则适合哪些标的（训练段和验证段都走得下去、样本外也没崩的）
- 某个标的为什么不适配：是成交笔数太少、期望收益为负，还是回撤超限

### 它不能回答什么

- 它评估的是单个标的上的表现，把适配的票凑在一起跑成一个组合是另一回事，组合里还有槽位竞争和资金分配
- 成交笔数过少的标的不能直接下结论，样本太少时适配分本身接近噪声，页面会按最少成交笔数把它们筛掉

### 口径提醒

- 严格按时间顺序切分，不会用后面的数据去训练前面的判断
- 评分是透明的：每一项的分量和当前取值都会列出来，不是一个黑箱总分

## 5. 策略实验室（/strategy-lab）

*回测与验证*

只说「在什么范围里买几只票」，剩下的排序指标、买卖条件、风控参数由系统在给定的历史区间里自动寻优，最后按留出期的表现排出榜单。

### 什么时候用它

- 手上还没有成形的规则，想先看看这段行情里什么样的配置走得最好
- 为自己的手工找一个起点，再把跑出来的配置拿回普通回测里人工复核

### 操作步骤

1. 设置品种范围和持仓数量这两个必填项
2. 可调整日期区间：默认用本地最新的已完成日线往前五年，也可以选全历史或自定义区间
3. 点击开始，系统先在候选空间里做大范围搜索，再对排在前面的配置做精细化
4. 查看排行榜：名次按留出段的表现排（夏普比率、年化收益），每一条都能展开看它的具体配置
5. 选中一条，用「回填」把它的排序指标、买卖规则、风控一起带回组合回测页，人工复核后再决定要不要用

### 它能回答什么

- 在给定的这段时间上，表现最好的那批配置长什么样
- 哪些参数区域是稳的（多次微调结果依然在前排），哪些只是孤零零的一个尖点

### 它不能回答什么

- 这本质上是一次大规模搜索，榜单第一名天然带挑选偏差：它是在同一批数据上从成百上千个候选里挑出来的，留出段成绩再好也不能当成未来的预期收益
- 一次实验只代表这一个区间的结论，换一段行情重跑得到完全不同的榜单是完全正常的

### 口径提醒

- 时间按顺序切成训练、验证、留出三段，留出段的数据不参与寻优
- 候选能否上榜由留出段裁定，而不是训练段，训练段好看但留出段不行的会被压下去

## 6. 策略追踪（/strategy-tracking）

*回测与验证*

把已经保存的策略作为历史参考，并从开始追踪日用初始资金和空仓启动新观察账户，之后每个交易日收盘后用最新行情重算。

### 什么时候用它

- 想知道一套刚定下来的策略，从今天开始往后到底还灵不灵
- 几套策略同时上线，横向比一比谁走得更稳

### 操作步骤

1. 先在组合回测或策略库里把这套配置保存成一个策略
2. 在策略列表里对它执行上线，上线日取行情库最新可用交易日；账户从原初始资金和空仓开始，规则从此冻结
3. 之后不需要手动操作，系统会每天重算一次，重算前会先确认没有正在跑的行情任务，避免读到半截数据
4. 在追踪页查看研究段绩效参考、上线后的观察曲线和每日资产记录；研究段的收益与持仓不带入观察账户
5. 关注衰减比和样本量。观察段太短时页面会明确标注样本过短，这时候不要急着下结论
6. 展开详情看最小跟踪记录长度：它会告诉你按目前的表现还要多少个交易日才能谈显著，以及还差多少
7. 展开后查看截至最近一次成功重算日的总资产、现金、当前持仓、浮动盈亏和卖出指标；停止追踪后保留最后一份快照
8. 当日候选每天扫描，不受周/月调仓日限制，按策略排名展示前 20 名和命中总数；它只是指标筛选结果，不是待执行订单
9. 「下一交易日计划」单独列出模拟器实际排定的卖出与买入；月/周频非调仓日可能没有买入计划
10. 成交明细只记录实际成交，可按上线前/后和成交日期筛选并翻页；同时显示信号日、费用、成本价和已实现盈亏

### 它能回答什么

- 从上线那天起到现在，这套策略在它没见过的数据上表现如何
- 上线前后的表现差了多少，这个差距是在扩大还是在收敛
- 按目前的表现，还要观察多久才够说它不是靠运气
- 最近一次重算时持有哪些标的、指标读数如何，以及次日模拟计划是什么

### 它不能回答什么

- 它是模拟观察，不连接任何券商、不产生任何下单。这里的「上线」是研究方法论里的概念，不是实盘
- 上线之后规则不可修改，改了就不是样本外了。要试新参数请新开一个追踪
- 观察段不足一定数量的交易日时衰减比基本是噪声，页面会标注但不会给出看起来很确定的数字
- 最小跟踪记录长度只回答「还要多久」，它通常比观察段长得多（年化夏普 0.6 大约要七八年）——那是提醒你再等等，不是判这套策略死刑
- 下一交易日计划的买入股数是按最近一个交易日收盘价估算的：明天的开盘价今天还不知道；今天收盘已经触碰止损 / 止盈 / 移动止盈的标的会列在卖出计划里，写明是哪条线、按哪天判定，明天开盘成交。明天**新**触碰什么，今天算不出来；卖出股数是持仓实际股数，那个今天就已经定了
- 浮动盈亏按最近可用收盘价估算，不含未来卖出费用；新版本之前没有保存的持仓快照会标记为「历史版本未保存」
- 旧成交的费用和成本价不会回推，会显示「未记录」；候选扫描不是下一日订单，只有成交流水里的记录才代表模拟实际成交
- 月度 / 周度调仓的策略在不是调仓日时不会给出买入计划——不是漏算，是那天本来就什么都不该做

### 口径提醒

- 每天是全量重跑而不是增量追加，所以结果与从头跑一遍等价；续跑时带数据指纹校验，行情一旦变动会直接报错而不是悄悄继续
- 某天失败只记录错误并停在原来的日期，不会跳过一天留下空洞
- 最小跟踪记录长度在观察段不足二十个收益率时不给数：偏度和峰度是三四阶矩，样本太少估出来的值能把结论翻好几倍，宁可不给
- 模拟成交统一一根 K 线滞后：买入、卖出规则、持有到期与止损 / 止盈 / 移动止盈都是当日收盘判定、下一根成交，界面标的价因此是判定当日的收盘价而不是成交价；风控线里的 ATR 用 Wilder 平滑，与指标目录的 atr_pct 同算法

## 7. 波段研究（/swing-research）

*规律研究*

先把行情切成一段段上涨和下跌，再看这些波段的起点附近，哪些指标出现过与平时明显不同的取值。

### 什么时候用它

- 想找出「一段上涨启动之前，通常会先看到什么」
- 为买卖条件研究提供候选方向，从这里知道该去挖哪些指标

### 操作步骤

1. 选择品种范围、日期区间，以及要对哪些指标做检查
2. 设置波段切分的参数，也就是反转幅度的阈值
3. 点击开始，系统先把每只股票的行情切成连续的涨段和跌段
4. 结果里有两种标签：一种打在波段极值点上（前一波的最低点或最高点），一种打在启动确认日上（已经涨满一定幅度、可以确认这波起来了的那天）
5. 看到靠谱的标签可以桥接到买卖条件研究，把「起点附近的指标特征」变成一条当天可判断、可被检验的具体条件

### 它能回答什么

- 一段上涨或下跌开始之前，哪些指标的取值与平时不同
- 这种不同是多少个波段的共同现象，还是个别案例

### 它不能回答什么

- 打在极值点上的标签属于事后视角：那个最低点只有在后面的行情走出来之后才知道。它解释过去很准，但不能直接当成买入信号，要用它必须先在买卖条件研究里改写成当天可判断的条件并验证
- 每段行情的第一段不打标签，它的起点只是数据窗口的边界，不是由行情确认出来的转折点

### 口径提醒

- 相邻两段共用一个转折点，所以「上涨起点」指前一波下跌的最低点，「下跌起点」指前一波上涨的最高点
- 启动确认日那一类标签的样本量远大于极值点标签，因为启动日可以有多个候选，而极值点每段只有一个

## 8. 个股研究（/individual-research）

*规律研究*

默认使用一只 A 股的全部本地历史，挖掘买卖条件、寻优退出风控，并自动回测最终候选供比较。

### 什么时候用它

- 只关注一只或少数股票，想为每只股票分别研究买卖信号
- 希望先在训练段发现条件，再验证止盈、止损和移动止盈组合，并把候选留给策略追踪

### 操作步骤

1. 从本地行情目录选择一只 A 股；默认使用该股票全部本地历史，也可改为最近五年或自定义区间
2. 设置 ATR 反转倍数、最短波段与预测窗口，并选择要搜索的指标和信号
3. 开始后系统按交易日顺序切分训练、验证、留出三段，训练段挖掘买卖条件
4. 训练段挖掘单指标条件及双指标 AND / OR 组合；每侧默认保留 10 条规则，验证段按夏普和年化收益分别排序买卖规则组合，每榜前五套去重后进入退出风控寻优
5. 百分比和 ATR 止损、固定止盈、移动止盈及冷却期按所选寻优强度计算
6. 查看最终双榜、三段绩效和全区间回测指标；所有最终候选都会自动回测，可对比策略收益、个股持有基准涨幅和超额收益
7. 在个股研究历史里比较每次运行时长，以及全区间年化最高候选的年化、对应超额、夏普和最大回撤
8. 保存后到策略追踪页检查股票代码和规则，再手动上线

### 它能回答什么

- 这只股票在自己的历史中，哪些指标状态更常出现在上涨或下跌波段启动前
- 哪些买卖条件组合在验证段取得较好的夏普或年化收益
- 入围规则配合哪些止盈止损参数后，在留出段表现如何
- 策略在完整区间跑赢这只股票买入并持有多少

### 它不能回答什么

- 这是单只股票的历史时间序列研究，不做横截面排序，也不能据此推断同一规则适用于其他股票
- 留出段只复核最终候选，不参与条件或风险参数排序；多次查看后再挑选仍可能形成新的选择偏差
- 低于验证段 5 笔或留出段 3 笔交易的候选仍会显示，但会标记样本不足；高回撤候选也保留并提示风险高
- 回测是本地日线上的单边做多模拟，不连接券商、不产生订单，也不代表未来收益

### 口径提醒

- 按所选股票的实际交易日切分 60/20/20，预测窗口跨越切分边界的日期会清除，避免前视标签泄漏
- 个股研究允许搜索指标库全部数值输出，包括不适合跨股票排序的价格尺度指标
- 买卖条件只从训练段指标与波段启动标签挖掘，验证段排序；止盈止损候选同样由训练段生成并由验证段排序
- 退出风控寻优只改变**已有仓位**的离场时点：训练段没有任何买入成交的买卖规则对不进入寻优（没有仓位就没有卖出、现金不变、之后的买入也开不了，3000 组参数的结果彼此恒等），整只标的会按「买卖规则候选在训练段没有任何买入成交」报出原因；买了但拿到期末没卖的规则对照常参与寻优——那正是止损与持有到期最能改变结果的一类
- 最终夏普榜和年化收益榜各复核前十名的留出表现；每个去重候选另做全区间回测供比较，两者都不改变验证段榜单顺序
- 持有基准按区间首日收盘买入、末日收盘估值且不计费用；超额收益按策略区间收益减去该基准涨幅计算
- 策略保存保留单股模式和完整配置；策略追踪由用户手动上线，追踪账户从上线日开始

## 9. 全市场策略池（/strategy-pool）

*回测与验证*

为每只本地 A 股分别研究年化收益与夏普最佳策略，查看当天买卖信号，并用共同留出段检验逐股策略组成的等权组合。

### 什么时候用它

- 希望把个股研究扩展到本地完整股票池，逐只保存能回测的买卖与退出风控规则
- 每天按买入信号、卖出信号和持仓状态检查当前策略池
- 对比年化收益和夏普目标下的策略池组合留出表现

### 操作步骤

1. 首次进入时选择关注年化收益或夏普；两类最佳策略都会保存，目标可以随时切换
2. 点击“清空并重建全市场”会先弹一次确认，写清删掉什么、留下什么——这一步删空整张策略池、误点就是几小时重跑，取消则什么都不发；确认后任务领取时删除当前策略池的自动策略、手动覆盖和失败记录，再按每只股票自己的完整本地历史切分训练、验证和留出（60/20/20，清除前视样本）；2016 年后上市的先用标的自己的前 268 根 K 线做指标预热，预热段不进入切分与全区间回测。行情与任务历史保留；“增量更新策略池”不删任何东西，不弹确认；按钮旁边的“待重算 N 只 · 可复用 M 只”在点之前就说清这一轮真正要逐只研究多少只，判定与任务预扫描同源（研究口径指纹没变、结果没欠账的才算可复用，弱策略到期与上线后衰减的仍然要重跑），研究参数一改就重算，有任务在跑时不显示这个数而是看进度条；历史样本不足的标的单独给一句“K 只样本不足已排期（最早 X）”：2016 年后上市、未满两年的排到“上市首日 + 730 天”（268 根预热 + 一年研究样本），在那之前每天重查都只会以同样的“不足”收场，其余每 30 天重查一次，到日子自动回到增量队列，不需要手动重跑
3. 默认从一只股票开始，每 30 秒最多增加一只并发股票，依据可用内存、实测内存增长和持续 CPU 压力动态调整；各股票的买卖规则验证和风险寻优共享进程预算，每只股票的进度条显示实时累计耗时，刷新页面后继续计时；每只完成立即保存，全市场标的状态随新结果自动刷新。进度行会把「历史样本不足」的标的单独列出来：它们绝大多数是上市历史不够长，本轮不产出结果，也不计入剩余时间预计；下一轮这些标的直接按排期处理（2016 年后上市、未满两年的排到“上市首日 + 730 天”，其余每 30 天重查一次），不再天天占着队列，到日子自动回来。若取消后要接着跑，点击“增量更新策略池”，复用行情和配置未变化的结果；再次点击清空重建则重新从头开始。旧信号快照不再作为新策略池的当前信号
4. 后台在新收盘行情完成后按行情交易日跟踪年化和夏普两套策略一次；打开页面只读缓存。手动点击“刷新当天信号”可重算两套账户
5. 全市场研究进行中时，自动跟踪最多每 30 分钟汇总扫一次：研究每完成一只都会产生新版本，按版本变化立刻重扫会让整条跟踪通道一直满负荷（2026-10-19 实测每 4 分钟一次、每次 53–164 秒扫 4,409 只），手动点「刷新当天信号」时只能排队。手动刷新不受这个下限限制；提交到后端的那几秒按钮会显示「正在提交…」
6. 「信号日期」下拉可以回看最近 10 个交易日：每个交易日给的是那天最后一次全市场扫描的结果，默认选中最新行情那天；选了更早的交易日就按那天的名单显示（面板标题不再写「当天 / 今日」，日期标在各面板右上角），那之后的逐股重跑不会并进历史视图，回到最新那天才看得到。更早的扫描结果会被清掉：每十分钟一次的全市场结果一份约 2 MB，2026-10-19 实测 17 天攒下 2.58 GB、占整库 62%；任务记录本身和耗时统计全部保留
7. 输入市场和代码可以单只重跑；相同规则保留创建时间，交易参数变化建立新跟踪版本，历史版本可在详情里查看
8. 点击“详情”查看两套策略的中文交易规则、当前查看区间的回测指标（策略收益、买入持有基准、超额收益、年化、夏普、回撤、胜率、盈亏比）、创建至今与上线后收益、持仓、收益曲线和成交明细；曲线标记创建日期，跨创建日持仓从原买入日整笔计入；成交明细每页 50 笔、默认最近成交在前，可切到最早成交在前，翻页条紧贴表格并显示第几页；明细同时给出成交日与信号日，页面不提供手工覆盖编辑
9. 标的太多看不过来时点击“关注”，这只股票就进入上方的“特别关注”面板：“全市场标的状态”的维护列、触发买入与卖出规则两个框的每一行、持仓中的每一行都有这个开关；已经关注的显示“取消关注”，再点一次就移出面板
10. “上线后收益榜”把当前目标下已有跟踪结果的标的按上线后收益排出前 20 名：可切换收益最高/最低在前，可按上线交易日设门槛（满 5、20、60 个交易日）；刚创建、还没有新行情的标的不出现在榜上，面板会说明有多少标的因为还没有生效版本或没有新行情被挡在外面

### 它能回答什么

- 当前目标下每只股票采用的最佳策略是什么，验证段指标和样本风险如何
- 哪些股票今天触发了买入或卖出规则；模拟组合持仓有没有触碰止损、止盈或移动止盈——触碰当日仍列在持仓里并写明是哪条线，下一交易日开盘才成交
- 年化目标和夏普目标各自构成的逐股策略组合，在共同留出期表现如何
- 上线模拟之后，哪些标的真的在赚钱、相对它自己的买入持有强多少，哪些其实一直在亏

### 它不能回答什么

- 策略是在每只股票自身历史中选择的，历史年化收益或夏普不保证未来有效，也不保证这些股票在同一市场环境下保持独立
- 全量研究使用默认 3000 组退出风控寻优；每只股票最多保留十组买卖规则候选，几千只股票可能需要很长时间。训练段一笔买入都没成交的买卖规则对不进寻优，也不占用那十个名额——风控只能改变已有仓位的离场时点，没有仓位时 3000 组参数跑出来的净值与基准恒等，这类标的直接按零成交报原因，不再空跑
- 留出段只用于复核，不能拿留出表现再次挑策略；多次切换目标和查看历史仍会带来选择偏差
- 当天信号是基于本地完整日线的模拟提醒，不发送外部通知，不连接券商，也不会下单
- 特别关注最多 100 只；已经不在策略池里的关注标的不会出现在面板中，会提示还有几只待重跑，不需要了可以在提示后一键移出

### 口径提醒

- 所有股票共用同一份本地已完成 A 股日线日历切分 60/20/20；标签预测窗口跨越边界的交易日会清除
- 训练段搜索买卖条件，退出风控候选按验证段排序；年化榜与夏普榜分别保存，留出数据不参与选策
- 标的状态默认按买入、卖出、持仓、空仓、无策略分组；点击指标列在「高→低 → 低→高 → 取消排序（回到按状态分组）」之间循环，点别的列从高→低重新开始，只改显示顺序；这一列取不到值的标的（无候选、创建至今待初始化或更新失败）无论升降都排在末尾
- 当天买卖信号列表可用「买卖信号排序」改按全区间胜率、盈亏比或全区间收益重排，指标缺少的标的排在末尾；只改显示顺序，不改变信号判定
- 组合槽位优先级使用所选目标的验证指标；同分时再比较另一目标、较低验证回撤和证券代码
- 全量重选只更新自动策略并保留手工覆盖；逐股重跑后的候选必须由用户明确应用
- 特别关注面板固定按触发买入、触发卖出、持仓中、今日无买卖信号、信号待刷新、无策略排序，不跟随全市场表的搜索、排序和分页；关注名单存在本地数据库，清空并重建全市场后仍然保留
- 全市场研究跑动中，这张表最少隔 20 秒才重取一次：一次重取是整张表（2026-10-19 实测 4439 行 / 7 MB），4 路并行每几秒就完成一只，逐次重取会让浏览器一直在解析与重排、点什么都卡。刚完成的标的会在下一次刷新时出现；任务完成、失败或被取消时不受这个间隔限制，立刻刷一次
- 任务记录分「研究与重跑任务」和「当天信号扫描」两组显示：后台跟踪每十分钟写一条扫描记录，分组后长跑的全市场任务不会被挤出列表。每条记录显示耗时、已完成数（其中新研究与复用各多少）、并行度和自动或手动触发；正在运行的行按页面秒表实时计时。上方汇总按任务类型各取最近 60 次终态记录算平均与中位耗时，「每只新研究标的」的耗时把被取消的半截轮次也算进去（总时长会随取消时刻变化，单只耗时不受影响），失败任务不计入任何平均值。任务被 worker 认领之后才开始计研究时长，之前入库的旧记录没有开始时间，耗时含排队并标注「含排队」
- 研究进度里那两个数不是同一个分母：「需重算 N 只」是预扫描剔掉可复用标的之后的真实工作量，「已完成」却把复用也计进去，所以剩余预计 = 队列 − 真正研究完的 − 失败的，平均每只耗时也只按真正研究完的算（复用几乎不花时间）。一轮里还没有任何一次正常完成的全市场重选时，「平均完成耗时」会写成「最近 60 次终态里没有一次正常完成」，而不是整条悄悄消失
- 策略详情的历史交易默认最近成交在前，可用「历史交易排序」切到最早成交在前；每页 50 笔由后端按当前排序切片，切换排序会回到第 1 页重新取，避免停在旧页码看到同一段成交的反序；同一天的成交保持成交先后（先平仓、后开新仓）
- 成交明细的买卖方向与收益曲线图例同词同色（买入绿色、卖出红色）；出场原因用中文（卖出条件、持有到期、止损、止盈、移动止盈），不再单列一列英文风控标记——它和中文原因是同一件事；最后一列是信号日，买卖规则与止损 / 止盈 / 移动止盈都在最新完整行情日收盘后判定、下一交易日才成交，所以信号日常比成交日早一天
- 持仓行上的风控条（止损 / 移动止盈 / 止盈三档价、判定日期、剩余持有交易日与到期日）取自引擎当日实际生效的配置，含该标的自己的 ATR 周期与最长持有天数；未启用的规则留空、不显示 0，到期日只有行情已经覆盖到那一天才给得出，否则只报还剩几个交易日
- 「最新收盘」列是这一行标的最后一根已完成日线的收盘价（不复权），由后端一次聚合直接从行情表取（60 秒内复用同一份结果），不依赖跟踪摘要，所以空仓、当天没有买卖信号、甚至还没有跟踪版本的行都有同一个数。它和持仓行上那三条风控线不一定同一天：风控线跟着跟踪快照的判定日期，行情却可能已经多走了几个交易日（停牌或那一轮跟踪没跑成），两个日期不一致时这一列会在价下面标出「价截至 X」，不假装它们是同一个时点
- 上线后收益榜读的是每个标的「当前生效版本」（手工覆盖优先于自动最优）的跟踪摘要：上线后收益从这一版策略自己的上线日算到它的行情截至日，标的之间起点和窗口长度都不同，所以榜上同时给出同期买入持有基准、超额、上线交易日和行情截至日；创建之后还没有新行情的后端结果是 0，那是「还没跑」不是「平盘」，不进榜。它与「创建至今收益」（跨创建日的承接持仓从原买入日算）不是同一个窗口
- 「策略 / 风险标记」列在单只标的研究失败时只显示一句「策略搜索失败 · 悬停查看原因」，原始报错放在鼠标悬停提示里；完整堆栈与原因看后端日志（搜「单只股票研究失败」），表格不铺长文本

## 10. 因子检验（/factor-test）

*规律研究*

把每一天、每一只股票都当成一个样本，看指标的排序能不能把未来若干天的收益排出先后。

### 什么时候用它

- 某个指标看起来像那么回事，想在全市场、长时间范围内认真确认一次
- 在把指标放进组合回测做排序之前，先知道它到底有没有预测力

### 操作步骤

1. 勾选要比对的指标，可以一次选多个
2. 设置前瞻天数，以及分层数量（按指标取值把当天所有股票分层）
3. 设置最少截面样本数，某一天样本太少时这一天直接不参与
4. 设置置换检验的次数和分块长度，用来判断这个相关性是不是运气
5. 跑完后查看：信息系数（预测力）、信息比率（稳不稳）、各层的平均收益是否单调（比单纯相关更强的证据），以及置换检验的原始 p 值与校正后的 p 值

### 它能回答什么

- 这个指标在整个市场、整段时间上的选股能力有多强
- 这个能力稳不稳定，还是某几天的极端贡献撑起来的
- 按它分层之后收益是不是真的单调，这是比「相关」强得多的证据

### 它不能回答什么

- 相关不是因果：指标能预测收益，不代表是它导致了收益
- 统计显著不等于能赚钱，还要看扣掉交易成本之后剩下多少，以及有限槽位下能不能买到那批股票

### 口径提醒

- 置换检验按交易日分块搬动标签（同一天的样本整体搬动），而不是逐个单元格打乱，因为同一天各只股票之间高度相关，逐个打乱会把有效样本量虚增几十倍
- 一次选多个指标时，错误发现率的校正对整组只做一次，而不是每个指标各做一次

### 下一步

- [把它用起来做排序](/portfolio-backtest)
- [看看已成交的单子上它表现如何](/factor-attribution)

## 11. 因子归因（/factor-attribution）

*规律研究*

拿一次已经跑完的回测，把赚钱的单子和亏钱的单子分成两组，比较它们在买入信号那天的指标取值有什么差别。

### 什么时候用它

- 一次回测下来有好单也有坏单，想知道差别到底出在哪里
- 验证自己的一个直觉：是不是某个指标高的那些才赚到了钱

### 操作步骤

1. 选择一条来源历史记录，必须是有成交明细的那几类回测（组合回测、适配性、单股等）
2. 勾选要比对的指标，可以是多个
3. 设置每组最少成交笔数、置换次数、分块长度和显著性水平
4. 点击开始，系统会先把每笔成交按先进先出配对盈亏，再分别取它们在买入信号日的指标取值
5. 读结果表：盈利组的均值、亏损组的均值、两者的差值、标准化后的差值、样本数、原始 p 值与校正后的 p 值

### 它能回答什么

- 这批赚钱的单子，在买入那天的指标取值上，跟亏钱的单子差在哪里
- 这个差别是否大到不像是随机分出来的

### 它不能回答什么

- 这是解释，不是预测。显著只说明赢亏两组的取值不像随机分出来的，它不代表以后按它买就能赢，到这里为止还没有验证过任何前瞻收益
- 它不产出「这个因子可用」的结论。要证明可用，得把这个想法拿到因子检验里去做前瞻性的统计检验
- 样本的基础是已经发生的成交。持仓中还没卖出的单子不计入胜负两边，它们的问题在这里没有答案

### 口径提醒

- 样本是每一笔成交，而不是行情面板上的每个格子。同一只票的多笔交易算多个样本，但它们之间并不独立
- 取的是买入信号日的取值，不是成交日的值，因为要解释的是为什么会买它
- 赢亏两组的证据一律用差值不用比值：指标的取值可以是负数，两个负数相除会被误读成差了好几倍
- 指标在信号日取不到值时，这笔成交直接丢弃而不是补零，丢了多少会写明
- 置换检验同样按整段连续的日期块搬动胜负标签

- [拿这个猜测去做前瞻性的统计检验](/factor-test)
- [回头调整规则再跑一次](/portfolio-backtest)

## 12. 候选库（/candidate-library）

*沉淀与复用*

买卖条件研究推荐出来的候选条件会在这里持久化保存，每条都带着当时的完整证据快照，可以采纳、淘汰、发布成策略，或者还原回研究继续调整。

### 什么时候用它

- 之前挖出来过哪些条件，现在还能被找回来
- 决定发布之前，重新核对一次当时据以下结论的那些证据

### 操作步骤

1. 浏览候选列表，可以按状态筛选（待定、已采纳、已淘汰）
2. 展开任意一条，查看它的证据快照：提升幅度、置换检验 p 值、参数敏感性、滚动复验结果
3. 决定去留：标记为已采纳或已淘汰
4. 「发布」会把它变成一条已保存策略，操作前有预览确认
5. 「载入复测」会把产生它的那次研究的配置还原回买卖条件研究页，方便在原基础上继续调整

### 它能回答什么

- 过去挖出来并且带完整证据的那些条件，现在剩了哪些
- 当时的结论是靠什么数据支撑的

### 它不能回答什么

- 这里没有任何自动上线的动作，采纳和发布都是需要你显式确认的一步，系统不会自己把任何东西变成策略
- 如果产生它的那次研究记录已经被淘汰（历史记录按类型只保留最近若干条），「载入复测」会明确提示无法还原，而不是点了没反应

### 口径提醒

- 目前只有买卖条件研究产生的条件能进候选库。其他类型的研究没有提升幅度和置换检验 p 值这类证据，硬塞进来只会得到一条没有证据、无法证伪的条目

- [发布成策略并往后观察](/strategy-tracking)

## 13. 标的检验台（/instrument-lab）

*沉淀与复用*

把注意力收到一只票上，同时给它三种读数：指标在它自己历史上的位置、一组规则在它身上的回测结果，以及已通过置换检验的条件在它身上是否成立。

### 什么时候用它

- 选股结果里冒出一只不认识的票，想快速看看它现在是什么状态
- 某个指标给出了卖出信号，想确认这个信号在它自己的历史上到底意味着什么

### 操作步骤

1. 输入或选择要查看的标的
2. 查看指标面板：关键指标的当前取值，以及它在自身历史上的分位，也就是今天是历史高位还是低位
3. 用一组规则在这只票上单独跑一次回测，看这套规则在它历史上的逐笔表现
4. 查看已经通过置换检验的那些条件，今天它身上有没有被触发

### 它能回答什么

- 这只票当前处于它自身历史的什么位置
- 某套规则在这只票上过去打得怎么样

### 它不能回答什么

- 单只票的样本极少，一只票的历史可能只有几十笔信号，这里的任何统计结果都不能当作结论，它是查看而不是证明
- 单票成交假设与组合回测一致（信号收盘确认、次日开盘成交），同样不含涨跌停约束

### 口径提醒

- 历史位置用这只票自己的历史数据算分位，不是拿它去和全市场比较

## 14. 回测历史对比（/history-compare）

*沉淀与复用*

把做过的实验摆在一起看：归一化曲线叠绘加上关键指标并排。它只读已经存下来的历史记录，不会重跑任何东西。

### 什么时候用它

- 同一个想法改了几版，想看到底是在变好还是只是在随机波动
- 不同类型的实验（组合回测、适配性、追踪）放在一起看相对表现

### 操作步骤

1. 在历史记录里勾选两到五条，可以跨类型
2. 选择叠绘或并排两种查看方式
3. 叠绘会把不同长度的曲线归一化到同一起点，便于看形状差异
4. 指标表把几条记录的关键数据放在一起，便于逐项对照

### 它能回答什么

- 几次实验之间的相对差异有多大，曲线形态上的差别在哪

### 它不能回答什么

- 只读历史、不重跑。如果两次实验之间行情更新过（比如后来又补了几天数据），严格来说这两条跑的不是同一份数据，对比时要把这一点算进去
- 它只比较结果的呈现，不会替你解释为什么这一版更好

### 口径提醒

- 叠绘前的归一化会把起点对齐，所以图上看的是形状与相对变化，不是绝对收益

## 15. 本地行情（/market-data）

*数据*

行情仓库的入口：查看目前覆盖到哪一天、同步最新日线、手动导入通达信文件、给行情做健康检查并一键重下有问题的标的，还能在 K 线图上查看单个品种。

### 什么时候用它

- 每天收盘后把行情同步到最新，后面的所有研究才有数据可用
- 有离线数据时从本地文件补录
- 怀疑某段行情有洞（缺口、停牌、异常价）时，先跑一次体检再决定要不要重下

### 操作步骤

1. 进页面先看状态：已覆盖的日期范围、品种数量，以及「交易日历停在 X，行情已到 Y」这条提示是否出现
2. 点「同步行情」：库里没有的标的从 2015-01-01 全量下载，已有行情的标的补到最新交易日，并顺手回看最近 10 天做逐值对照（上游改写了近期数据才会覆盖，没变就不写库）；已经拉到本交易日收盘的标的当天不再问一次，同一范围在同一个交易日里第二次点会直接回「本地已覆盖 X 收盘，无需下载」而什么都不下载，怀疑近期数据被上游改写过时勾「强制重新下载」绕过这条判定，结果里的「已覆盖本交易日 N 只」就是这一轮没问的标的数
3. 中间那段行情写歪了才用「删除并重下全部历史」：它先删掉范围内标的的全部日线（含本地导入）再整段重下，最慢但唯一能覆盖已有区间；行情比交易日历新时，面板会提示日历还停在哪天
4. 需要补录时用文件导入（通达信 day 文件）
5. 点「开始检查」跑一次只读体检，六项检查会分别列出命中的标的与证据
6. 对有问题的项点「修复」：删掉命中标的的全部历史再全量重下覆盖。一次只修名单最前面的 500 只（名单按市场+代码排序），剩下的会报出只数并给「继续修下一批」，从第 501 只接着修
7. 选中某个品种可以看它的日线、月线、年线 K 线，叠加均线、RSI、MACD
8. 长期用下来数据库会变大，可以在这里做备份与压缩整理

### 它能回答什么

- 本地数据到底有多少、最新到哪天、缺哪些品种
- 行情有没有洞：缺口、连续缺失段、异常跳变、价格结构错误、零成交、数据陈旧

### 它不能回答什么

- 只有日线，没有分钟级数据，所以盘中级别的策略没法在这里验证
- 只有 A 股，ETF、指数、债券、B 股不在同步范围内

### 口径提醒

- 所有页面读的都是同一个本机数据库，行情一更新，之前算好的指标缓存会失效并按新数据重算
- 当日尚未收盘的数据被标记为未定稿，不参与筛选和回测，避免把没走完的一天当成已知事实
- 健康检查的交易日是从数据里选出来的：某天有行情的标的数达到全市场峰值的半数才算交易日，宁可多报缺口也不放过一个
- 「修复」是先删除这些标的的全部历史再重新下载，在线源已经没有的标的（如退市）会变成空数据，结果里会单独列出来
- 缺口和连续缺失段大多来自长期停牌：在线源同样没有那几天，重下改不出任何东西。判定办法是看结果里「删了多少、回来多少」——两个数一样就说明这批缺口不是下载问题，别再反复修（2026-10-16 实测一批 500 只：删 1,133,865 根、原样写回 1,133,865 根，体检各项数字一项都没变）
- 修复分删除、下载、合并三段，进度条的百分比是「本阶段」的：合并阶段会从下载阶段的位置掉回去，所以它旁边永远跟着阶段名与实测速率。并发下载时显示的那只只是「某一路 worker 最近上报的」，同时在传的还有另外七只
- 修复会独占行情库几分钟，这期间提交的全市场研究会因为打不开库而失败：要修行情就等研究跑完，或者先停掉研究

## 16. 使用手册（/user-manual）

*附录*

把各页面能回答什么、不能回答什么，以及每个数字背后的口径汇总在一起。网页版带目录和关键词搜索。

### 什么时候用它

- 忘了某个功能在哪一页、它是干什么的
- 看到一个数字想确认它是怎么算的（口径）
- 想反过来找：哪个页面能回答我现在这个问题

### 操作步骤

1. 网页版左侧目录列出全部页面，点一下就跳到那一节
2. 在搜索框里输关键词，目录会收窄成命中的页面，正文里命中的字会高亮；多个词用空格分开表示都要出现
3. 标题或摘要命中的页面整节都留着，只有要点命中的页面只留那几条——目录项上的数字是该页命中了几条
4. 每一节末尾的「下一步」是从那个页面出发的常见去处，直接点就能过去
5. 每个功能页顶部也有同一份说明的折叠块，想不起来时不必翻手册

### 它能回答什么

- 每个页面一句话是干什么的
- 某个数字是怎么算的、哪些情况被排除了（口径提醒）
- 这个功能做不到什么——「它不能回答什么」是逐页写明的

### 它不能回答什么

- 它只讲本产品自己的口径，不教交易，也不评价策略好坏
- 搜索是字面包含匹配，不做分词和同义词。手册里只写了「佣金」时搜「手续费」是搜不到的，换个词再试
- 高亮只说明这个词出现在这一条里，不代表这一条就是你要的答案
- 只有网页版能搜。Markdown 版（docs/user-manual.md）是同一份内容的顺序阅读版

### 口径提醒

- 内容只有一份，就是仓库里的 pageGuides.json。页内折叠说明、这一页、docs/user-manual.md 三处都由它生成，所以不会出现三处说法不一致
- 口径跟着代码走：改了算法就要改这里，改了这里三处会一起变
- 目录顺序与各功能页的导航顺序一致，便于对照
