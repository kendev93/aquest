# 在线行情上游接口审计与解耦记录

审计日期：2026-08-30（2026-09-18 移除 TDX 通道后修订）

本项目只使用内置在线客户端获取行情。本文件记录在线 HTTP 接口的核对结果、`.day` 文件格式约定，以及上游变化时需要重新验证的检查清单。

在线客户端直接使用 East Money 证券列表接口获取代码/简称，使用 East Money K 线接口获取未复权日线；日线接口失败时切换到腾讯 JSONP 日线接口。业务层只接收项目自己的规范化 DataFrame，不直接暴露上游响应；provider、版本、列表指纹和同步错误会写入 DuckDB 元数据。

## 1. Provider 范围

East Money 是唯一在线 provider，它覆盖：

- A 股：沪市主板（`t:2`）、科创板（`t:23`）、深市主板（`t:6`）、创业板（`t:80`）；
- 场内基金：ETF/LOF（`b:MK0021,b:MK0022,b:MK0023,b:MK0024,b:MK0827`）。

B 股、指数和债券没有可用的在线日线来源，范围校验会在发起请求前直接报错，而不是静默跳过。基于 TDX 协议的在线通道已于 2026-09-18 移除（公共服务器不再稳定响应，且其品种范围已被 East Money 覆盖），因此不再保留 `tdx_protocol/`。

## 2. 在线接口的两个关键行为

这两点在 2026-09-18 的排障中确认，改动 `OnlineMarketClient` 时必须保持：

1. **每页硬截 100 条**：请求 `pz=5000`（甚至 `pz=500`）时服务端仍只返回 100 行，真实总数只在响应体的 `total` 里。因此翻页判断必须依据 `total`，**不能**把"本页行数少于请求页大小"当成最后一页——那样只会取到第一页，而目录按代码倒序返回，第一页全是 `989xxx`/`970xxx` 这类非 A 股代码，过滤后一个标的都不剩。
2. **限流表现为软错误**：服务端既可能返回 HTTP 200 + `{"rc": 102, "data": null}`，也可能直接断开连接。两种都必须转成 `OnlineProviderError`（`_reject_failed_payload` + `_fetch_catalog` 重试），否则"证券列表为空"会被当成正常结果，同步会以 0 标的、0 错误"成功"结束。

## 3. 在线 HTTP 接口变更检查清单

1. 验证 East Money 列表接口仍返回 `f12`/`f14` 代码和名称字段，并检查沪深 A 股数量没有异常骤降（正常约 5500 条）；
2. 验证列表接口仍然把每页截成 100 条，且 `total` 与逐页累加结果一致；
3. 用固定响应 fixture 验证 East Money `klines` 的日期、开高低收、成交量和成交额字段转换；
4. 用固定 JSONP fixture 验证腾讯日线的字段顺序、成交量/成交额单位转换和日期裁剪；
5. 验证 `rc != 0`、连接被断开、空响应、超时、重复日期和单标的失败隔离；
6. 验证未复权原始价格口径不会与开发兼容读取的 `.day` 数据混用；
7. 在 Docker 中通过 `pip check`、导入检查和 provider 能力接口确认依赖与版本。

## 4. `.day` 系数和证券类型

项目不把未知代码段按股票兜底。当前识别范围与已审计实现一致：

| 市场 | 类型 | 代码段 | 价格系数 | 成交量系数 |
| --- | --- | --- | ---: | ---: |
| SH | A 股 | 60、68 | 0.01 | 0.01 |
| SH | B 股 | 90 | 0.001 | 0.01 |
| SH | 指数 | 00、88、99 | 0.01 | 1.0 |
| SH | 基金/ETF | 50、51、52、53、55、56、58 | 0.001 | 1.0 |
| SH | 债券/回购 | 01、10、11、12、13、14、20 | 0.001 | 1.0 |
| SZ | 股票/B 股 | 00、20、30 | 0.01 | 0.01 |
| SZ | 指数 | 39 | 0.01 | 1.0 |
| SZ | 基金/ETF | 15、16、17、18 | 0.001 | 0.01 |
| SZ | 债券 | 10、11、12、13、14 | 0.001 | 1.0 |

金额字段保持 `.day` 中的 float32 元值；价格不做复权。业务层使用统一的 `stock/fund/index/bond` 类型，并为非股票类型标记虚拟研究回测。修改系数、字段或 DuckDB schema 时，先补迁移/备份和回归测试。

## 5. 明确不移植的能力

项目没有移植或调用上游财经客户端的以下模块：

- Web 路由、CLI、MAC、分钟线、海外/扩展市场、资金流和财务数据；
- 上游的 `SignalScanner`、策略对象、回测引擎、组合引擎和绩效分析器；
- 上游离线写回 `.day` 的 append/sync API。

业务代码只接收项目自己的 `InstrumentRef`/`StockRef`、规范化 DataFrame、`MarketDataRepository` 和回测结果。行情 schema 由本项目自己拥有并维护；在线同步写入本机 DuckDB 的行情表，不涉及任何外部行情库。
