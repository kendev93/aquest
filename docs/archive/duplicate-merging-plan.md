# 挖掘结果相关性去重（backlog #4）

> 目标：让候选表里的 N 条是 N 个**不同**的发现，而不是一个发现的 N 个阈值。
> 2026-09-21 定稿。

---

## 一、现状：去重已经有了，但太严且静默

`condition_research/mining.py` 现有一条去重规则 `_masks_agree`：两条候选的命中样本集合
Jaccard（交/并）≥ **0.995** 时，只保留排序靠前的那条。

两个问题：

1. **0.995 太严，拦不住"阈值差一点"**。同一个指标的两个相邻分位阈值（比如 `ma5 ≥ q0.6`
   与 `ma5 ≥ q0.8`），后者是前者的子集，Jaccard 只有 ~0.5，于是五条一起进了候选表
   —— 这正是 backlog 里写的"看起来像五个发现"。
2. **被合并的条件是静默消失的**。用户不知道系统替他丢了什么。这跟我们
   「能被证伪、不藏东西」的立场冲突：一条被删掉的条件和一条没挖出来的条件，
   在界面上长得一模一样。

所以这次要做的其实是两件事：**把门槛放宽到一个有意义的水平** + **把被合并的条件显式列出来**。

---

## 二、度量：φ 系数（布尔命中向量的皮尔逊相关）

两条候选在**双方都可评估的样本**上各有一个布尔命中向量，φ 就是这两个向量的皮尔逊相关系数。

### 为什么不用纯 Jaccard

Jaccard = |A∩B| / |A∪B| 直观，但"0.5 算不算同义"没有外部锚点，门槛只能拍。
φ 是相关系数，有通用解释，且多了两个 Jaccard 没有的性质：

- **能分正负**：ρ ≈ −1 是"互补条件"（`a > b` 与 `a < b`），是**相反**的发现，不是同一个。
- **对"两者都没命中"的样本敏感**：两个都极少命中的条件，Jaccard 会因为分母小而显得
  重合度高，φ 则会因为大量双阴性样本而把真实重合度压下来。

两者单调相关（Jaccard 高 ⇒ φ 高），不需要同时暴露。

### 计算口径

两条候选的可评估样本空间不同（不同指标各有各的 NaN 段），所以 φ **只在两者都可评估的
样本交集上算**。用 2×2 列联表：

|  | B 命中 | B 未命中 |
| :--- | :--- | :--- |
| **A 命中** | n11 | n10 |
| **A 未命中** | n01 | n00 |

```
φ = (n11·n00 − n10·n01) / √((n11+n10)(n01+n00)(n11+n01)(n10+n00))
```

分母为 0（例如两者并集恰好覆盖全部可评估样本）⇒ **无法判定，保守保留两条**。
不猜、不凑数。

### 取 ρ ≥ 门槛，不取 |ρ| ≥ 门槛

ρ ≈ −1 是互补条件，不是同义条件。而且它们**不可能同时优于基线**：两者把样本切成两半，
加权平均就是基线本身，所以不可能两边都高于基线。取符号不影响实际结果，但口径清楚。

### 性能

φ 需要 |V_A ∩ V_B|（两个可评估样本集合的交集大小），朴素算法是每对候选做一次全样本
布尔与，候选上千时会拖垮挖掘。两点优化：

1. **valid mask 位打包**：每个不同的 valid mask 打包成 Python int 一次（O(n/64)），
   之后每对只需一次 `&` + `bit_count()`，微秒级。
2. **Jaccard 前置剪枝**：可以证明 φ ≥ t 蕴含 Jaccard ≥ t / (2 − t)
   （在命中集合占比趋于 0 的极限下取到）。先算便宜的 Jaccard，低于这个界就直接跳过 φ。
   t = 0.7 ⇒ 先要求 Jaccard ≥ 0.538，绝大多数候选对在这里就被排除了。

## 三、门槛：默认 0.7

嵌套阈值（同一个指标、一个包含另一个）可以解析地算：设外层命中 q·n、内层命中 p·n
（p ≤ q），则

```
φ = √( p·(1−q) / (q·(1−p)) )
```

用默认分位（0.2 / 0.4 / 0.6 / 0.8）代入：

| 关系 | φ |
| :--- | :--- |
| 相邻分位（`≥ q0.6` vs `≥ q0.8`，即 40% vs 20%） | **0.61** |
| 相邻分位（`≥ q0.4` vs `≥ q0.6`，即 60% vs 40%） | **0.67** |
| 隔一个分位（`≥ q0.2` vs `≥ q0.6`，即 80% vs 40%） | 0.41 |
| 不同但同向的指标（`ma5 > ma20` vs `ma10 > ma20`） | 0.7 ~ 0.85 |
| 同一指标、方向相反（`ma5 > ma20` vs `ma5 < ma20`） | ≈ −1（不合并） |
| 无关的指标 | < 0.3 |

**默认 0.6**，可配 0.5 ~ 1.0。

于是默认分位下，一个指标的 4 个阈值会收敛成 **2 条**（"前 40%" 与 "前 80%" 各一族），
而不是 1 条也不是 4 条：**同一个发现的相邻切点合并，相隔一个分位的保留**——后者代表
不同的激进度，是另一回事。

实测（合成数据，一个真信号 + 一个加了 5% 噪声的副本）：门槛 1.0 时 5 个名额被
「同一条信号的 5 个写法」占满；0.6 时收敛成 1 条主候选 + 噪声指标的候选。

**1.0 ≈ 关闭**：此时仍保留原有的 0.995 Jaccard 兜底（几乎完全相同的命中集合照样合并），
所以"调到 1.0"不等于完全没有去重，文档里要写清楚。

---

## 四、报告：被合并的条件必须看得见

- 每条**保留**的候选多带一个 `duplicates` 列表：被合并掉的条件文本 + φ + lift + 样本数。
- 前端在条件名下方显示「已合并 N 条同义条件」，悬浮列出明细。
- 候选名额是**在完整排序上继续往下走**的，所以被合并掉的位置会自动由更靠后的、
  不同义的条件顶上——去重不是"少给几条"，是"给几条不一样的"。

---

## 五、不做

- **不做跨买卖两侧去重**：两侧的样本集不同（买 = 每次入场 1 条，卖 = 持仓期每个决策点
  1 条），φ 没有共同的可评估空间。
- **不做"去重后再补挖一轮"**：不需要，排序是完整的，循环自然往下走。
- **不做"这几个条件属于同一族"的聚类标签**：只说"它和谁同义"，不做族划分——
  族划分需要一个"族内全部两两同义"的假设，实际上不满足（A~B、B~C 但 A≁C 是常态）。
