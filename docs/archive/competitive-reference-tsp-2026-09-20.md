# 对标参考：tick-stock-panel（TSP）→ 我们可借鉴什么

> 数据取自 GitHub API 与仓库 README，核对日期 2026-09-20。
> TSP：4840 星 / 1202 fork / MIT / 2026-06-18 开源 / 886 commits。

## 一、先说结论

TSP 的功能面比我们宽，但**宽的方向和我们的定位不是同一个方向**。

它涨星主要靠三块：盘中异动监控 + 推送、市场环境/连板梯队、AI 助手。这三块恰恰是**我们不该跟的**——它们要么需要分钟级数据和常驻进程，要么需要额外数据源（fuyao/ths/龙虎榜），要么把产品从"日线研究工具"推向"盯盘终端"。

真正值得借鉴的，是它**补在我们已知缺口上的那几块**，尤其是验证链路（滚动样本外、参数敏感性）和因子检验的产品化。

## 二、全景对照

| 功能域 | TSP | 我们 | 判断 |
| :--- | :--- | :--- | :--- |
| 自定义指标/因子 | DSL，25 算子点选编辑器 | **通达信公式解析**（兼容真实 TDX 语法） | 我们更强，不动 |
| 指标流水线 | 68 列一次扫表落盘 | 指标缓存（按年分块 + float32，5218 只 × 5 年 2GB） | 持平，各有取舍 |
| 条件/因子挖掘 | 嵌套样本外 + 相关性去重 + 组合搜索 | 条件研究：置换门槛 + BH-FDR + 60/20/20 切分 | **统计更严谨，但缺滚动验证与相关性去重** |
| 挖掘结果处理 | 候选库 + 显式发布，永不自动上线 | 勾选候选后追加到规则并重跑 | 借鉴"显式发布"的产品表达 |
| 因子检验页 | IC/IR、分层收益、多空组合、Newey-West | IC/ICIR/分段同号 已在 ranking.py 算，但**只服务于排序推荐，没有独立页面** | **值得做成一等公民** |
| 回测验证 | 参数敏感性 + 滚动样本外 + 蒙卡回撤 | 单次 60/20/20 切分（**已知缺口：非 walk-forward**） | **优先补** |
| 回测归因 | 因子归因：胜单/败单入场信号日因子对比 | 无 | 与我们的立场一致，值得做 |
| 组合回测 | 因子/策略/分钟三层，T+1/费率/滑点 | 动态组合回测（槽位等额/固定股数、ATR 止盈止损） | 持平；分钟级我们没有数据 |
| 策略寻优 | 无（靠挖掘与因子库） | 策略实验室（5 年寻优 + 排行榜 + 回填复核） | 我们更强 |
| 适配/防过拟合 | — | 策略适配性评估（训练/验证/测试 + 透明适配分） | 我们独有 |
| 市场环境 | 情绪周期 6 阶段 + 概念/行业主线 | 无 | 需额外数据源，谨慎 |
| 盘中监控推送 | 竞价/盘中/偏移 + 语音播报 + 飞书 | 无 | **不建议做**（见下） |
| AI 助手 | 18 个只读工具、流式、工具足迹卡 | 无 | 若做，学它的"足迹可核对" |
| 部署 | `docker run` 一条命令，GHCR 预构建多架构镜像 | `docker compose up -d --build` | **该抄，1~2 天** |
| **品种覆盖** | **仅 A 股个股**。ETF 只在"持仓提醒"和"数据同步"两处出现；科创板/创业板/北交所只在异动偏离值口径里作为涨跌幅规则出现，不是独立品种支持。无港股、无美股、无债券、无 B 股 | 股票 / B 股 / ETF 基金 / 指数 / 债券，条件研究可在股票与 ETF 间切换 | 我们更宽，但见下方说明 |

## 二之二、品种覆盖：宽不等于强

我们支持的品种比 TSP 多，但这里要诚实：**多出来的部分大多不产生研究价值**。

| 品种 | 对指标研究的意义 |
| :--- | :--- |
| 股票 | 主战场，两边一致 |
| ETF / 基金 | **有价值**——免印花税、可按行业/宽基做轮动，且和 参照产品 的受众天然重叠 |
| 指数 | 有价值，主要用作择时基准和对照轨 |
| 债券 | 技术分析意义有限，流动性低 |
| B 股 | 几乎无人交易 |

所以真正的分野是：**TSP 做"个股深度 + 盘中"，我们做"品种广度 + 研究严谨"**。广度里真正能守住的是 ETF 与指数，债券和 B 股属于历史兼容，不值得为它们投入新功能。

这个分野不用互相靠拢——补 TSP 的深度要分钟数据和额外数据源，我们补不了；它补我们的广度同样要重构指标口径。

## 三、建议借鉴清单

### P0 — 与定位一致、直接强化核心卖点

1. **滚动样本外（walk-forward）验证**
   现在条件研究是 60/20/20 单次切分，结果依赖这一次怎么切。改成多窗口滚动（例如 5 个滚动窗口），报告每个窗口的一致性。复用现有切分逻辑，工作量中等。
   *这是 memory 里已记录的已知缺口，也是"防过拟合"最直接的补强。*

2. **参数敏感性分析**
   挖出的阈值，看它在邻域内稳不稳（阈值上下浮动 ±10/20%，收益曲面是否悬崖）。工作量中低，产出是一张热力图——**是"这条结论靠不靠谱"最直观的证据**。

3. **挖掘结果的相关性去重**
   TSP 有，我们 `condition_research` 没有（`strategy_discovery` 只有 trade-behavior 去重）。对候选条件的命中序列算相关，剔除 |ρ| 过高的同义条件。工作量低。
   *不做的话，候选表里会出现五条本质相同、只是阈值差一点的条件，看起来像五个发现。*

4. **单指标/因子检验页**
   IC、ICIR、分层收益、多空组合——`condition_research/ranking.py` 已经在算了，只是藏在"排序推荐"里。抽出来做成独立页面，工作量中等，收益是**我们最稀缺的能力终于有了一个正门**。

### P1 — 值得做，但不紧急

5. **候选库 + 显式发布**
   现在"勾选后追加到规则并重跑"是一次性动作。借鉴 TSP 的"候选入库、显式确认才发布、永不自动上线"——把它做成一个持久的候选库，带采纳状态。工作量低到中。
   *价值在于表达：我们把"自动给你策略"明确拒绝掉，这件事本身就是卖点。*

6. **因子归因（胜单 vs 败单的入场信号日指标对比）**
   和我们的可信度立场完全一致，工作量中等。回答的是"为什么这批单赢了、那批输了"。

7. **一条命令部署（GHCR 预构建镜像）**
   不是功能，但影响最大：别人点进来的第一眼。工作量 1~2 天。

8. **回测闭环**：结果 → 保存候选 → 一键载入复测。我们有回填，可以做得更顺。

### P2 — 谨慎，先别动

9. **AI 对话助手**：2026 年它是流量，也是大工程。若做，**必须学它的"工具足迹卡（参数与耗时可展开核对）"**——让 AI 每次取数可核对，这和我们的立场是同一件事；一个黑箱 AI 助手会砸自己的招牌。
10. **市场环境 / 情绪周期**：需要概念、行业、连板数据，我们目前只有日线。且偏"择时"，稀释"严谨选股"定位。
11. **扩展数据插件化**：前提是先有第三方数据，现在没有。

### 明确不抄

| 不抄什么 | 为什么 |
| :--- | :--- |
| 盘中异动监控 + 语音播报 + 飞书/企微推送 | 需分钟级数据 + 常驻进程 + 7×24 运维；把产品推向盯盘终端 |
| 连板梯队 / 龙虎榜 / 财务四表 / 概念行业轮动 | 全都需要额外数据源（fuyao / ths），我们手上只有日线 |
| 分钟级回测 | 无分钟数据 |
| 持仓提醒 Lots（买入批次 → 自动止盈止损） | 偏实盘记账，且我们的定位明确是"研究工具，不碰实盘" |

这四块恰恰是 TSP 涨星的主力。但对我们是**定位稀释 + 数据源缺口 + 运维负担**三重叠加，跟了会付出最大代价、拿到最小收益。

## 四、借鉴时的方法论

- **抄产品形态，不抄统计口径。** TSP 的 IC/分层/Newey-West、情绪周期 6 阶段都是它自己定的口径，我们没有验证过。抄过来等于把自己的可信度押在别人的定义上。要做就自己定口径、写进文档、能证伪。
- **每个新增展示型功能都要过一关：它能不能被证伪？** 不能证伪的图表会稀释我们的核心卖点——我们和TSP最大的区别就是"敢给结论打可信度标签"。
- **别为了对齐功能表而做功能。** 上面 P0 四条有个共同点：都是把我们**已经算出来的东西**变成用户看得见的证据。这比对齐功能表划算得多。
