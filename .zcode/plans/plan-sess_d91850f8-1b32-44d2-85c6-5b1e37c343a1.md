# P0 实施:线程上闸 + stage_durations 落日志

按双方确认的修正版顺序执行,本轮只做 P0(后续 P1/P2 等 P0 基准数据回来再动)。

## 改动内容

**1. DuckDB 线程上限** — `selector_app/market_data/store_base.py`
- 仿照 `_duckdb_memory_limit`(`@lru_cache(maxsize=1)` 保证整进程 config 一致,避免 DuckDB 拒绝同文件异配置连接)新增 `_duckdb_threads()`:读 `SELECTOR_DUCKDB_THREADS`,非法值与 `0` 按未配置处理(回 DuckDB 默认);
- `_open`(:256-263)把 `threads` 并入 connect config。
- 单测:`tests/unit/test_duckdb_store.py` 补用例——设 env 后 `current_setting('threads')` 生效、未设时保持默认、非法值忽略(用 `cache_clear()` 处理 lru_cache)。

**2. BLAS/OMP 上限** — `selector_app/strategy_discovery/worker.py`
- 模块顶部(`import os` 加入 stdlib 块,语句放在所有 selector_app 导入之前——numpy 导入后再设不生效):`os.environ.setdefault` 四个变量 `OPENBLAS_NUM_THREADS`/`OMP_NUM_THREADS`/`MKL_NUM_THREADS`/`NUMEXPR_MAX_THREADS` = "1";spawn 评估子进程继承环境一并覆盖;`setdefault` 保留用户显式配置。

**3. stage_durations 落日志** — `selector_app/strategy_pool/service.py` `_research_symbol`
- `individual_service.run()` 返回的 `stage_durations_seconds`(:426-430)目前被池记录(:498-512)丢弃;在指纹校验通过后加一行 `logger.info`(json 紧凑输出,含 market:code/name),单股/全市场两条路径都覆盖。

**4. 配置与文档**
- `.env.example`:`SELECTOR_DUCKDB_THREADS=1`(激活项,含中文说明:只注入策略 worker、为什么默认 1、设 0 恢复默认)+ BLAS 四变量注释条目(显式覆盖用);
- `docker-compose.yml` strategy-worker environment 追加 5 个透传(`SELECTOR_DUCKDB_THREADS:-1` + BLAS 四个),backend 不加——同步/导入保持全核;
- `docs/standalone-deployment.md` 环境变量表追加两行,表格后加一句:这两组上限压住"隐形并行"后,调大 `SELECTOR_STRATEGY_POOL_MAX_WORKERS`/`SELECTOR_DISCOVERY_WORKERS` 才有真收益。
